# 广告主与代理商使用手册

本手册面向通过 W8M 投放广告的广告主，以及受托查看或审核广告主、广告活动和广告组的代理商。内容包括账户职责、投放流程、广告素材与定向、计量口径、外部需求方竞价接入和常见问题。平台地址、账户启用、商务规则和生产接入信息由平台运营方另行提供。

当前平台已经实现 CPM 投放保护、素材校验、转化归因、分账户报表、人工账单和
外部 DSP / ADX 需求方接入。管理 API、强化登录与权限、流量质量审查、托管付款
以及真实外部竞价流量都由运营方分别启用；页面或代码中存在入口不代表生产环境
已经开放。平台不支持自动竞价/机器学习，也不把旧 CPC、CPA、ROI 记录当作可用
竞价策略。各功能的实现与启用状态见[文档与里程碑索引](README.md)。

## 1. 账户与职责

系统使用以下与投放有关的角色：

| 角色 | 主要职责 |
|---|---|
| 广告主（`adv`） | 维护自己的账户、广告活动、广告组、广告素材、定向、预算、投放报表和竞价端点。 |
| 代理商（`agent`） | 受托查看广告主、广告活动和广告组，并执行被授权的审核流程。 |
| 平台运营人员（`admin`） | 管理账户状态、竞价端点凭据与启用、外部需求方路由、流量分配和结算视图。 |

代理商账户不是另一个广告主账户，也不自动取得广告主的全部编辑权限。需要创建广告素材、定向或竞价端点时，应由对应广告主账户操作；需要审批、启用、凭据或路由变更时，应联系平台运营人员。

登录地址以运营方提供的域名为准。广告主页面位于：

```text
https://<平台域名>/goto/adv/g/...
```

代理商页面位于：

```text
https://<平台域名>/goto/agent/g/...
```

如果现有密码无法登录，请使用登录页的“忘记密码”功能，或联系平台运营方确认账户状态。

### 账户安全与双重验证

平台启用账户安全功能后，登录除了密码，还需要身份验证器生成的六位验证码；
也可以在无法使用身份验证器时输入一枚尚未使用的恢复代码。首次登录会先进入
“账户安全”页面：把页面显示的一次性设置密钥或标准 TOTP 地址加入身份验证器，
输入当前验证码确认，并立即把系统生成的恢复代码保存到离线安全位置。设置完成
前，系统不会开放投放和报表页面。

密码至少需要 12 个字符。修改或找回密码后，现有登录会话全部失效，需要重新
登录。登录后的“账户安全”页面可以更新恢复代码；更新后旧代码立即失效。停用
双重验证需要当前验证码和操作原因，也会退出所有设备。普通退出使用页面内的
退出按钮，系统会撤销当前会话；不要仅靠关闭浏览器窗口。

“忘记密码”链接只发送到广告主账户登记邮箱，并在短时间内失效。已经启用双重
验证的账户还必须提交一枚恢复代码，密码更新、恢复代码消费、会话撤销和安全
审计才会作为一个事务完成。如果邮箱不可用，或身份验证器和恢复代码同时丢失，
请联系平台运营人员按线下身份核验和审计流程重置；客服不会要求你发送 TOTP
设置密钥、当前验证码或恢复代码。

代理商只取得明确授予的查看/审核能力。只读分析人员也只能查看逐资源授权的
报表，不能修改投放、竞价端点、凭据引用、路由、账户或实验。页面上看不到某个
按钮不等于权限控制；系统以登录身份、账户归属和服务端权限为准。

### 广告主管理 API（可选）

平台启用此功能后，广告主可在工作台的“管理 API 凭证”页面签发最小权限的
服务凭证，用于自有系统管理广告活动、广告组、素材、定向并读取投放报表。该
凭证不能登录网页，也不能管理流量方、账单、付款、竞价端点审批或平台路由。
签发、轮换和撤销都要求最近一次双重验证及操作原因；令牌只显示一次，应立即
保存到受控密钥系统，不能发送到聊天、工单或源码仓库。

所有写请求都要携带同一个重试用 `Idempotency-Key`，修改已有对象还要携带页面
或接口返回的最新 `ETag`。返回 202 仅表示配置已保存，需继续查询 operation，
等缓存状态变为 Active 后才表示投放节点已收到配置。详细字段、配额、错误和
示例见[广告主管理 API 契约](advertiser-management-api.md)。Active 是缓存发布
确认，不会跳过广告活动的“新建”或广告组的“待审核”状态，也不等同于已经具备
投放资格。

## 2. 投放对象的层级

常规本地投放按以下层级组织：

```text
广告主账户
└── 广告活动（Campaign）
    └── 广告组（Ad Group，系统内部对象名为 Item）
        └── 广告素材（Creative）
```

- 广告活动定义名称、投放时间、流量范围、活动级预算和启用状态。
- 广告组定义价格、计费方式、落地页、频次控制、广告组预算、媒体与流量条件。
- 广告素材定义尺寸、媒体类型、内容、权重和启用状态。
- 定向条件附着在广告组上；广告主、广告活动和广告组还可以共同决定流量方、网站/App 及行业的允许或屏蔽范围。

一个请求只有在账户、广告活动、广告组、广告素材、时间、预算、尺寸、定向和供应侧规则都允许时，才可能参与竞价。仅把最下层广告素材设为启用，并不能绕过上层状态或规则。

## 3. 推荐投放流程

### 3.1 检查账户资料

登录后先检查账户名称、联系人、地址和密码。仪表盘可显示主要广告组和广告位表现。投放账单、人工调整及账户启用状态以平台运营方出具的记录为准；不要把页面中显示的“已保存”理解为一定已经具备投放资格。旧版“余额管理/付款”入口已停用，平台不会在工作台采集完整银行卡号或银行账户信息。

### 3.2 创建广告活动

进入“广告活动”，选择新建并填写：

- 活动名称和可选的外部业务编号；
- 开始与结束时间；
- 投放时区和可选的每周投放时段；
- 投放节奏（尽快投放或按时间均匀投放）；
- 说明、目标类型和流量范围（白名单/黑名单）；
- 总预算和每日预算；
- 启用状态。

时间区间、预算和流量范围会影响所有下属广告组。建议先保存为未启用状态，完成广告组、广告素材和定向检查后再启用。

### 3.3 创建广告组

在广告活动下创建广告组，至少检查以下内容：

- 广告组名称；
- 计费方式和价格；
- 落地页；
- 开始与结束时间；
- 可选的每周投放时段和投放节奏；
- 总预算与每日预算；
- 展示次数、展示周期和最小展示间隔；
- 点击次数与点击周期；
- 语言、设备、位置、MIME、素材特征及行业规则；
- 启用状态。

当前唯一受支持的本地计价方式是正数 USD CPM（千次展示价格）。系统先按最高有效 CPM 选择广告组，再仅在同一获胜广告组内按素材权重轮播；提高素材权重不会让低价广告组超过高价广告组。上游底价为空或为 `USD` 时可参与；系统不做其他币种换算，其他币种的底价会使该广告位不出价。一个有效展示的账务金额按 `CPM / 1000` 计算，例如 CPM 为 `2.5` 时，该次展示计入 USD `0.0025`。

历史数据中可能仍有 CPC、CPA 或 ROI 字段，但当前运行时不会用固定系数自动换算。此类广告组不能参加竞价，必须由广告主和运营方确认新的 CPM 后再迁移；不要把原数值直接改名为 CPM。

频次控制只在当前请求通过隐私决策并允许个性化处理时采用用户或设备标识。平台可在本地短暂使用买方用户 ID、用户 ID 或 IFA/设备 ID，但写入频控与测量状态前会转换为不可逆的域隔离 HMAC 假名；上下文或受限流量不会把 IP 与 User-Agent 拼成后备身份。缺少合规身份时仍可投放上下文广告，但跨请求频控和上传人群不会生效。

### 3.4 理解预算、时段与投放节奏

广告活动和广告组各自可以设置总费用、总曝光、总点击以及对应的每日上限。任一已设置的上限耗尽后，该广告组就不再参加新的竞价；数值为 0 或留空表示该项不限。把上限下调到不高于已经消耗的数值，会在运行缓存传播后停止后续竞价。

时间规则按以下口径执行：

- 广告活动和广告组的开始、结束时间使用 UTC，边界时刻包含在可投放区间内；
- 每日预算和每日计数在 UTC 00:00 切换到新的日期；
- 广告活动的“投放时区”只用于解释星期一至星期日的每周投放时段；广告组继承该时区；
- 活动时段和广告组时段必须同时允许，广告才可参加竞价；不启用每周时段表示全天允许；
- “尽快投放”只受硬上限和时段限制；“按时间均匀投放”按 UTC 当日或有效活动周期已经过去的比例逐步开放预算，不会自动修改出价；
- 均匀投放不是流量预测或自动优化。时段很窄、可用流量不足、定向过严或较晚开始投放时，预算可能无法用完。

活动/广告组列表中的累计消耗来自展示、点击日志的账务聚合，不是每次竞价后立即更新的余额。竞价路径同时在 Redis 中做原子预留，以避免并发请求越过硬上限；展示成功后预留会确定，loss 或响应生成失败会释放。共享 Redis 不可用时，有预算限制的本地广告会停止参与，而没有预算限制且不依赖其他 Redis 状态的广告可继续按现有规则处理。

默认运行缓存最长允许 15 分钟。运营方应至少每 5 分钟发布一次完整投放缓存；发布持续失败时，带投放策略的旧候选到期后会停止竞价。因此，页面保存与所有竞价节点生效之间存在有上限的传播窗口。

### 3.5 添加素材

在广告组下添加广告素材，并填写素材名称、尺寸、媒体类型、素材来源、权重和启用状态。素材尺寸必须与目标广告位完全一致，权重只用于同一广告组同一价格下的素材轮播。

当前渲染规则包括：

- Banner 只接受一个绝对 HTTP(S) 图片或 HTML 文档地址，不接受直接粘贴的 HTML；
- 视频只接受一个绝对 HTTP(S) 媒体地址，系统在投放时生成 VAST；
- 原生素材使用标题、说明、行动按钮、图标和主图等结构化字段，不接受任意原生 JSON 或 HTML；
- Banner、视频和原生素材都必须与请求的媒体类型、尺寸和 MIME 相容；安全广告位要求全部素材、落地页和跟踪地址使用 HTTPS；
- 原生素材会带有 DSP 展示跟踪，并以 DSP 点击跳转地址作为主链接；
- Banner iframe 会带有 DSP 展示像素；
- Banner 若要使用 DSP 点击测量，素材来源 URL 必须显式使用 `{CLICK_URL}`；
- `{LANDING_URL}` 表示直接的广告主落地页；
- 系统不会重写任意第三方 iframe 或 HTML 内部的点击链接。

管理和审核页面只显示经过转义的素材来源，不会加载或执行素材。素材的实际投放效果应通过测试广告位验证，而不是把第三方代码粘贴到管理页面预览。

因此，上线前应在测试环境实际点击素材并检查最终跳转。不要手工修改系统生成的 `/imp`、`/clk`、`sig` 或 `sig_ts` 参数；修改、过期或未签名的测量地址会被拒绝。

### 3.6 配置定向

广告组可组合以下定向类型：

- 地理：国家、州/省、城市、DMA、ISP、邮编、经纬度和连接类型；
- 人群：性别、年龄/出生年份区间和语言；
- 设备：操作系统、版本、浏览器/平台和设备类型；
- 时间：日期、小时、星期和时区；
- 供应与内容：流量方、网站/App、广告位、行业及流量范围；
- 上传人群：广告主上传的用户或设备标识集合。

空的普通定向通常表示不限。上传人群的语义更严格：配置了多个上传标识类型时，请求必须同时包含并命中每个已配置类型。并且，只要有候选广告组命中上传人群，系统会优先在这一组候选中选择，而不会再把普通组合定向候选放回同一次选择。

上传人群只用于已获允许的本地个性化匹配，不会转发给外部 DSP / ADX。集合默认从最后一次写入起保留 30 天；到期或按核验请求删除后，需要重新上传才能再次命中。不要上传未取得合法来源和相应用途授权的标识符。

建议先用较宽规则完成小流量验证，再逐项收紧；发生无投放时，按“状态与时间 → 预算 → 尺寸 → 供应侧流量范围 → 人群定向”的顺序排查。

### 3.7 上线检查

提交上线或请求运营方协助前，逐项确认：

- 广告主、广告活动、广告组和至少一个广告素材均处于可投放状态；
- 当前时间位于广告活动和广告组的投放区间；
- 总预算和每日预算未耗尽；
- UTC 时间区间、活动时区和每周投放时段符合预期；
- “尽快投放”或“按时间均匀投放”的节奏选择符合本次投放目标；
- 素材尺寸与目标广告位一致；
- 落地页及第三方监测地址可从公网访问；
- Banner 点击监测需要时已使用 `{CLICK_URL}`；
- 价格和底价使用兼容币种；
- 定向与供应侧流量范围没有互相排斥；
- 修改已进入运行缓存。若页面已保存但行为未变化，请联系运营方检查缓存刷新和运行节点。

## 4. 报表与计量口径

广告主仪表盘和报表可查看近 24 小时数据、主要广告组和主要广告位。数据由日志聚合与账务定时任务生成，因此不是请求级实时数据。

当前常规投放口径如下：

- 展示：有效 `/imp` 跟踪到达后计入；
- 点击：有效 `/clk` 跟踪到达后计入；
- 花费：以展示跟踪记录中的已服务 USD eCPM 为基础；
- Win/Loss：用于分析，不单独作为当前账务花费依据；
- 未触发展示像素的已赢竞价，不会仅凭 win 回调计入常规展示花费。

系统会尽力抑制重复的有效展示和点击事件。共享状态服务暂时不可用时，平台仍优先接收签名有效的测量事件，因此短时间内可能出现重复计量；遇到明显异常时，请向运营方提供发生时间、广告活动、广告组和广告素材信息。

“市场分析”按当前登录广告主强制隔离，可按广告活动、广告组、素材、流量
方、流量源、广告位、国家/地区和设备查看展示、点击、CTR、花费和有效
CPM。时间统一使用 UTC，金额为六位小数 USD；报表中的金额已经按每次有效
展示换算，不能再次除以 1000。页面同时显示时间片、日汇总、转化接收和外部
需求方回调的高水位。`partial` 表示资料仍不完整，`unavailable` 表示来源不可
用，两者都不能理解为真实的零。

代理商账户暂不提供该市场分析视图，直至平台建立可核验的代理商—广告主
委托关系。需要代理查看时，应由运营方按正式权限流程开通，不要共享广告主
密码或在网址中传入其他账户 ID。

### 流量质量审查与申诉

平台启用“流量质量审查”后，广告主只能查看本账户已披露的案件、规则版本、
信号分类、观测值/阈值、证据完整度、处理状态和执行状态。Redis/MySQL 故障、
超时、无填充、素材格式错误或外部需求方响应错误不会自动被认定为无效流量；
证据缺失或不完整时只记录观察结果，不会拦截投放或改变账务。

如果人工复核结论为“无效流量”，可在案件页面提交一次有界、具体的申诉理由，
由独立管理员复核。请说明 UTC 时间、广告活动/广告组/素材和业务背景，不要提交
Cookie、设备标识、竞价令牌、完整请求正文或个人资料。任何暂停投放或账单暂停
都必须关联可追溯的规则版本和人工结论；原始展示、点击、转化和账务事实不会被
删除或改写。

### 转化行为与归因

本地广告的有效点击跳转会在落地页地址中附加
`w8m_action_token`。广告主后端可以保存该令牌，并按平台的签名
`POST /action` 契约回传以下分析行为：普通转化、购买、下载、视频播放
完成，以及形如 `namespace.name` 的自定义行为。不要把令牌放入公开日志、
客服工单、第三方分析维度或继续转发的 Referrer。

“转化与归因”报表按当前登录的广告主隔离，显示行为总数、点击归因、浏览
归因、未归因、迟到行为和购买金额，并与同期曝光、点击和花费核对。点击在
默认 30 天窗口内优先于浏览；浏览默认窗口为 7 天。系统只认同一条签名
竞价/广告素材链路，不做跨设备猜测。当前所有转化和行为均为分析指标，不
增加 CPM 账单、不扣减余额，也不改变预算预留。

回传端收到 `503` 时，应在令牌仍有效期间使用同一 `event_id` 和完全相同的
行为内容重试，并为新请求重新生成时间戳和签名。相同内容只记录一次；同一
广告主重复使用 `event_id` 表示不同内容会返回冲突。详细字段、签名算法和
状态码见[转化与归因契约](conversion-attribution.md)。

平台支持由运营方审核启动的对照实验。实验按稳定假名分组，仅记录经过登记
的曝光以及主指标、护栏指标观测，不会自动调高出价、改变预算或跳过素材
审核。广告主应先明确实验假设、时间范围、分组比例、主指标和停止条件；没有
完成曝光登记的数据不能作为实验结果。实验结果使用 UTC 和既有报表口径，
不得把同一转化重复登记为多个结果。

## 5. 外部 DSP / ADX 需求方接入与竞价

如果广告主还经营可接收 OpenRTB 请求的外部 DSP，可以在“竞价端点”中维护自有端点：

```text
/goto/adv/g/bidder?action=topics
```

广告主可编辑：

- 端点名称；
- HTTPS/HTTP 端点 URL；
- OpenRTB 版本；
- Seat；
- 超时时间。

凭据状态和启用状态对广告主可见，但以下内容由平台运营方管理：

- 端点身份凭据、审批和启用；
- 参与竞价的流量方、流量源和广告位范围；
- 路由、超时和加价规则；
- 报表归属与结算配置。

请通过约定的安全渠道向运营方提供接入凭据，不要将密钥写入端点名称、URL 或其他普通表单字段。

审批后，外部需求方有两种可能的触发方式：

- `Fallback`：仅在本地广告无法填充时请求外部端点；
- `Always`：在平台总开关和 Always 独立开关都启用时，也可与本地广告竞争，最终按可比较的有效 CPM 选择赢家。

端点还必须通过自身对应的合成广告组流量范围检查，才会收到相关流量方、网站/App 或广告位的请求。路由成员关系不代表无条件获得全部流量。

外部 DSP 应注意：

- 外部披露还需要平台单独启用隐私开关；每个端点只收到分配给它的展示位和独立清理后的上下文 OpenRTB 请求；
- 平台不会转发用户/设备标识、IP、原始 UA、精确位置、人口属性、搜索/查询内容、未知字段或未受控 `ext`；只添加受控的 `ext.request_domain` 和合作式点击信息；
- 迟到、非法、低于底价或非 USD 的响应会被丢弃；
- 平台保留下游广告代码，但用平台签名的 `/mid/*` 地址代理 win、loss 和 bill 回调；
- `burl` 优先作为可计费事件；没有 `burl` 时，win 才是计费回退；
- 合作式点击通知地址位于 `ext.aofei_middleman.click_notify_urls`，下游素材需要主动接入；平台不改写任意 `adm`；
- 广告主报表按外部 DSP 应付侧花费展示；平台结算口径由运营方另行说明。

新增或修改端点后，应等待运营方完成审批、凭据和流量路由配置，再进行流量测试。
运营方会先在不放量的状态核对路由发布和凭据引用，再以 Fallback 小流量灰度；
只有 Fallback 的隐私、素材、回调、重试和收费/应付/差额对账全部通过后，才会
另行评估 Always。广告主保存端点或看到“已启用”，不等于已经获得生产流量。

### 账单与人工结算

广告主账单按 UTC 日、UTC 自然周（周一至周日）或 UTC 自然月，从已完成的日账务汇总生成。账单金额使用 USD，保留六位小数；点击不会重复计费。需要账单或 CSV 时，请向平台运营方提供账户 ID 和账期，不要通过邮件或工单发送完整银行卡号、银行账号或路由号码。

账单状态依次为草稿、暂停、已确认、已结算或已更正。调整必须保留原因；制单、确认和结算登记由不同的授权运营人员完成。已确认/已结算账单如需更正，会保留原记录并建立替代账单，不会回写展示事实或降低投放预算硬上限。

### 托管付款（由平台启用时）

如果运营方已启用“广告账户资金管理”，广告主可在工作台查看自己的账单、
付款申请和托管客户绑定。首次使用可建立 Stripe 托管客户；该绑定需由另一名
授权人员复核。对状态为 `Confirmed`（已确认）的账单，可按不超过账单剩余可
申请金额的 USD 美分金额提交付款申请。独立复核通过后，再点击“前往托管付款
页”，在 Stripe 页面填写付款信息。

W8M 页面不会要求、接收或保存完整卡号、银行卡号、路由号码或支付验证码。
不要把这些资料填入“操作原因”、工单、邮件或聊天。付款页返回并不代表账单
已经结算；最终状态以签名回调、服务商对账和平台账单记录为准。页面显示
`Submitting` 或 `Submitted` 时不要另建请求号重复付款，应先联系运营方按原幂等
请求核对。账单进入 `Held`（暂停）后不会发起新的托管付款。

## 6. 常见问题

### 有素材但没有竞价

检查上层对象是否启用、时间和预算是否有效、尺寸是否匹配、底价币种是否为 USD，以及定向、行业与供应侧流量范围是否过窄。若刚修改配置，联系运营方确认缓存已发布。

### 页面显示还有预算，但仍然没有竞价

先检查每日上限是否已经在当前 UTC 日期耗尽，以及活动/广告组每周时段是否同时允许。页面计数来自账务聚合，Redis 中还可能包含尚未进入报表的并发预留；为防止超投，系统以较保守的一方为准。持续不一致时，请运营方检查账务时间片、投放缓存生成时间和 `delivery:budget:*` 状态，不要直接清空 Redis 键。

### 有 win 但报表没有展示或花费

当前账务以展示跟踪为准，而不是只看 win。检查素材中的展示像素是否被客户端加载，并确认报表处理时间是否已经覆盖对应测试时段。

### Banner 有展示但没有点击

确认素材明确使用 `{CLICK_URL}`。系统不会自动包装任意 iframe 内部链接。

### 上传人群导致投放明显减少

确认请求能提供全部已配置标识类型，且值已存在于广告主上传集合。上传人群命中具有优先层级，配置时应避免意外排除其他候选广告组。

### 竞价端点显示已保存但没有流量

保存端点信息不等于已经启用。请运营方检查端点审批、身份凭据、流量范围、路由状态和平台功能开关。
